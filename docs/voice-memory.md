# Говорящие встречи: голосовая память и уверенность меток

Дополняет `docs/meeting-folder.md`.

Код: движок — `engine/mostik_engine/voices.py` (хранилище, модель голоса, подсказки), `speaker_confidence.py` (уверенность), `meeting_speakers.py` (правка говорящих в готовой расшифровке); приложение — `MostikCore/MeetingSpeakers.swift`, `Mostik/SpeakersController.swift`, `MostikUI/MeetingSpeakersViews.swift`. Тесты — `engine/tests/test_voices.py`, `test_speaker_confidence.py`, `MostikCoreTests/MeetingSpeakersTests.swift`.

## Говорящие в расшифровке

У реплик системной дорожки в `transcript.json` два поля: `label` — исходная метка диаризации («Собеседник 2»), `speaker` — видимое имя. Имена меток хранятся в `speaker_names` (`{"Собеседник 2": "Мария"}`). Переименование меняет только имя, поэтому его можно повторить или исправить. Реплики-перекрытия «Собеседник 1 + Собеседник 2» получают имена обеих частей.

Дорожка микрофона — всегда «Я». Её не переименовывают, не оценивают и не отдают голосовой памяти.

В окне встречи над расшифровкой есть панель «Говорящие». Для каждой метки там есть «Назвать» или «Переименовать», а если голос узнан — подсказка «Похоже на голос: X · 74 %» с кнопками «Да, это X» и «Нет». После правки движок переписывает `transcript.json`, `transcript.md` и `meeting.md`.

## Уверенность меток

Диаризация transcriber (Sortformer или FluidAudio) уверенности по репликам не отдаёт: в `system-transcript/speakers.json` есть только отрезки `{start, end, speakers}`. Поэтому Mostik считает её сам. Для реплики длиной `d` секунд:

- `ov_A` — сколько секунд реплики покрыто отрезками назначенного говорящего (у перекрытия — объединение обоих);
- `ov_B` — то же для самого заметного другого говорящего;
- `share = min(1, ov_A / d)` — доля окна за назначенным;
- `margin = max(0, (ov_A − ov_B) / (ov_A + ov_B))` — зазор до второго, 0, если оба нуля;
- **`confidence = 0,5 · share + 0,5 · margin`**, округление до сотых.

| Случай | Уверенность |
|---|---|
| Реплика целиком под одним голосом | 1,0 |
| Половина реплики в тишине, соперника нет | 0,75 |
| 80 % — назначенный, 20 % — другой | 0,7 |
| 60 / 40 | 0,4 |
| Поровну с другим голосом | около 0,2 |
| Диаризация реплику не покрыла, transcriber приписал её ближайшему | 0 |
| На всей дорожке один голос | 1,0 — путать не с кем |

Ниже **0,6** реплика идёт на проверку: `review: true` и `speaker_alternatives: [{label, share}]` — другие говорящие по доле окна. Если в окне никого нет, альтернативы — соседи по времени (`share: 0`), не больше трёх. В корне `transcript.json` есть поле `speaker_review` — число таких реплик.

В окне встречи у такой реплики стоит плашка «Метка под вопросом · 42 %» с кнопками альтернатив («Анна · 35 %») и «Верно». Выбор альтернативы переносит реплику на другую метку. После «Верно» и после выбора у реплики появляется `reviewed: true`, и с проверки она снимается.

## Голосовая память

**Выключена по умолчанию.** Настройки → «Голосовая память» → «Узнавать собеседников по голосу». Первое включение открывает экран согласия: что хранится, где, как работает и как стереть, плюс предупреждение, что голос — биометрические данные. Без согласия (`voiceMemoryConsent`) память не включается, даже если править файл настроек руками.

Как работает:

1. Встреча расшифровывается. Если память включена, движок считает вектор голоса для каждой метки системной дорожки, у которой не меньше **4 с** речи. Перекрытия не берутся.
2. Векторы кладутся в `voices/pending/<id встречи>.json`. В папку встречи они не попадают. Вектор метки удаляется, как только по ней принято решение («Да», «Нет» или имя), файл — когда решать нечего или через **30 дней**.
3. Каждый вектор сравнивается с людьми из памяти. Оценка человека — лучший косинус среди его образцов. Подсказка появляется, если лучший **≥ 0,62** и опережает второго человека **на 0,08 и больше** (пороги heed, MIT). Один человек подсказывается только одной метке, той, где совпадение сильнее.
4. Подсказка не подставляется молча. Имя попадает в расшифровку только после «Да, это X» или когда вы сами назвали говорящего. Тогда вектор этой встречи добавляется к образцам человека. Если такое имя уже есть, образцы сливаются; регистр и лишние пробелы не важны.
5. «Нет» убирает подсказку, и для этой встречи она больше не появится (`voices.rejected`).

### Где лежит

`<MOSTIK_HOME>/voices/`, по умолчанию `~/Library/Application Support/Mostik/voices/`. Папка `0700`, файлы `0600`.

```json
// people.json
{"schema": "mostik.voices", "version": 1, "people": [
  {"id": "3f2a9c1b7d4e", "name": "Мария", "created": "…", "updated": "…",
   "samples": [{"vector": [256 чисел], "model": "fluidaudio-wespeaker-v2-256",
                "seconds": 182.4, "meeting": "2026-10-11-153000", "added": "…"}]}]}

// pending/2026-10-11-153000.json
{"schema": "mostik.voices.pending", "version": 1, "meeting": "…", "model": "…", "created": "…",
 "clusters": {"Собеседник 2": {"vector": […], "seconds": 182.4}}}
```

- Аудио не хранится, только векторы. На человека — до **10** образцов. Одиннадцатый вытесняет самый старый, повтор с той же встречи заменяет прежний.
- Векторы разных моделей несравнимы: у образца есть поле `model`, и сравниваются только образцы той же модели.
- В `transcript.json → voices` — только подсказки (`label`, `person_id`, `name`, `score`, `second`), список меток с векторами (`pending`), слишком короткие метки (`short`) и, если модели не было, `available: false`.

### Забыть

- «Забыть» у человека в Настройках удаляет его образцы, подсказки с ним во всех встречах и нерешённые векторы встреч, похожие на его голос.
- «Забыть всех» стирает папку `voices/` целиком: людей и векторы встреч. Подсказки из расшифровок убираются.
- Имена, которые вы уже поставили в расшифровках, остаются: это текст встречи, а не голос.
- При выключении памяти приложение спрашивает «Стереть отпечатки?» (по умолчанию — да) и шлёт `voices_wipe`. Если оставить, новые векторы не считаются, накопленное ждёт «Забыть». Встреча, которая в этот момент расшифровывается, отпечатков не допишет ни в том, ни в другом случае: стирание и выключение меняют эпоху памяти, а встреча запомнила эпоху на старте и после смены пишет без голосов (`voices.LOCK`, `voices.revoke`).

Переименование человека в Настройках на имя другого человека из списка объединяет их образцы.

### Модель голоса

Интерфейс — `VoiceEmbedder` (`model_id`, `available()`, `embed(audio, spans)`). Боевая реализация — `FluidAudioEmbedder`: `fluidaudiocli process --mode offline` из transcriber. CLI отдаёт отрезки своей диаризации с вектором WeSpeaker v2 (pyannote community-1, CoreML, 256 чисел, лицензия CC-BY-4.0). Вектор метки Mostik — среднее векторов отрезков FluidAudio, взвешенное по секундам пересечения с репликами метки. Бинарник и модели уже стоят у transcriber (`skills/transcriber/bin/macos-arm64/fluidaudiocli`, `~/Library/Application Support/FluidAudio/Models/`), ничего не скачивается. Прогон идёт на CPU с пониженным приоритетом. На синтетической записи голосами macOS (30 с) он занял около 13 с под нагрузкой. Косинус одного голоса между записями — 0,71, разных — 0,36–0,43.

Если бинарника или моделей нет, Настройки показывают «Нужна модель голоса», а переключатель недоступен. Расшифровка при этом не падает: в `voices` пишется `available: false`.

Для тестов есть `StubEmbedder` — детерминированный вектор из sha256 ключа голоса.

## Протокол движка

| Команда | Поля | Ответ |
|---|---|---|
| `voices_config` | `enabled` | `{enabled}`. Приложение шлёт при запуске движка и при переключении; `true` — только после согласия |
| `voices_status` | — | `{enabled, available, detail, model, people: [{id, name, samples, seconds, updated}]}` |
| `voices_rename` | `person_id`, `name` | `{person_id, name, merged, people}`; имя другого человека — слияние |
| `voices_forget` | `person_id` или `all: true` | `{forgotten, people}` |
| `voices_wipe` | — | `{forgotten, meetings, people: []}`: стирает `voices/` целиком и подсказки в расшифровках; флаг памяти не меняет |
| `speaker_rename` | `folder`, `label`, `name` | `{label, name, person}`; `person` — `{person_id, name, merged, samples}`, если память включена и у метки есть вектор |
| `speaker_confirm` | `folder`, `label` | то же, имя — из подсказки |
| `speaker_reject` | `folder`, `label` | `{label}` |
| `speaker_turn` | `folder`, `turn`, `label` (пусто — «Верно») | `{turn, label, speaker}` или `{turn}` |
| `speaker_unname` | `folder`, `label` | `{label, name, removed}`: «Убрать имя» — метка снова «Собеседник N» |
| `speaker_merge` | `folder`, `source`, `target` | `{source, target, moved, speaker, person}`: «Объединить с…» |

Одно имя — один человек. `speaker_rename` с именем, которое уже носит другая метка встречи (без учёта регистра), не заводит второго человека: метка сливается с той, у ответа есть `merged_from`. Старые расшифровки, где у двух меток одно имя, сворачиваются при первой правке говорящих; до неё приложение показывает таких говорящих одной строкой.

Голосовая память при правке имён:

- Слияние меток: вектор каждой берётся из `pending/` или из образца этой встречи у человека, которому метку уже назвали. Общий вектор — среднее, взвешенное по секундам речи. У человека остаётся один образец этой встречи с общим вектором (прежний заменяется), так что обе половины голоса учат одного человека. Если у слитой метки нет имени, общий вектор ждёт решения под оставшейся меткой. Если у второй метки было другое имя, образец этой встречи с того человека снимается.
- «Убрать имя» и переименование в другое имя: образец этой встречи снимается с прежнего человека; человек без образцов удаляется. При включённой памяти вектор возвращается в `pending/` и станет образцом, когда метку назовут снова. Без памяти отпечатки не пишутся, только снимаются.

Ошибки правки (метка «Я», нет такой метки, нет подсказки) приходят с кодом `speaker`. Команда `meeting` сама берёт флаг памяти из `voices_config`; его можно передать и полем `voice_memory`.
