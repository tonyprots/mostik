# Имена говорящих на встречах: откуда их взять

Исследование: как размечать спикеров автоматически, без ручного «Собеседник 2 — это Петя».

## Что уже есть в Mostik

- **Диаризация** (Sortformer, при 5+ голосах FluidAudio) делит дорожку системы на «Собеседник 1, 2…». Имён она не знает.
- **Дорожка микрофона** всегда «Я» — свой голос размечен без ошибок.
- **Голосовая память** узнаёт людей по образцам голоса, но только после подтверждения, выключена по умолчанию.
- **Календарь** отдаёт список участников события (`calendar_terms.py`, `attendees`) — уже идёт в подсказки ИИ встречи.
- **Кадры окна звонка** — снимки окна встречи с OCR (Vision), выключены по умолчанию, согласие на каждую встречу.

Не хватает одного звена: связать метку диаризации с именем в момент речи.

## Варианты

### 1. Accessibility: имя активного говорящего из окна приложения — главный

Приложение читает дерево Accessibility окна Zoom: список участников и индикатор «сейчас говорит». Моменты смены индикатора сопоставляются с репликами системной дорожки.

- Так делает **Granola** для Zoom на Mac: читает имена участников и индикатор активного говорящего из десктопного Zoom ([документация Granola](https://docs.granola.ai/help-center/taking-notes/speaker-attribution-zoom)). В веб-Zoom и на Windows не работает.
- Открытый **[lucassynnott/meeting-notes](https://github.com/lucassynnott/meeting-notes)** (MIT, macOS, Swift) — то же самое: имя ставится, только когда один говорящий явно доминирует в отрезке, и никогда не угадывается; имена из Zoom заодно учат голосовые отпечатки.
- **[pasrom/meeting-transcriber](https://github.com/pasrom/meeting-transcriber)** (MIT) читает участников через Accessibility только в Teams.
- **Recall.ai Desktop SDK** (коммерческий) отдаёт настоящие имена для Zoom, Meet, Teams без бота; их же блог описывает самостоятельный путь — системный звук плюс имена через Accessibility или разбор интерфейса ([Desktop Recording SDK](https://www.recall.ai/product/desktop-recording-sdk), [как собрать самому](https://www.recall.ai/blog/how-i-built-a-botless-meeting-recorder-from-scratch)).

Плюсы: без записи экрана, без бота, локально, в реальном времени. Разрешение Accessibility у Mostik уже есть (нужно для вставки текста).
Минусы: своя разметка под каждое приложение, ломается при обновлении интерфейса. Для Zoom путь доказан чужими продуктами. **Телемост на Mac — Qt 6** (не Electron): Qt отдаёт дерево Accessibility, но есть ли там имена плиток и признак говорящего — неизвестно, нужно снять дерево на живом звонке.

### 2. Снимки экрана и OCR — запасной для всего остального

Идея автора. Раз в ~1 с снимать окно встречи в малом разрешении: в режиме «говорящий» крупная плитка подписана именем, в галерее говорящий обведён рамкой. Имя — OCR (Vision), говорящий — по крупной плитке или по цвету рамки.

Плюсы: одинаково для Телемоста, Meet в браузере, VK Teams, Teams; основа уже есть (ScreenCaptureKit, только окно приложения с микрофоном, OCR Vision).
Минусы: нужно разрешение «Запись экрана» и согласие (по каждой встрече); при демонстрации экрана плиток не видно — имена в эти отрезки не будет; рамку активного говорящего надо настраивать под каждое приложение; OCR путает похожие имена — сверять со списком участников из календаря.

### 3. Отдельная дорожка на участника из самого Zoom — точный, но не в реальном времени

В настройках десктопного Zoom есть «Record a separate audio file for each participant»: при **локальной** записи в папке `Audio Record` появляется файл на каждого участника, имя файла начинается с имени человека ([инструкция](https://chrismenardtraining.com/post/zoom-record-separate-audio-tracks-for-easy-editing/), [GVSU](https://services.gvsu.edu/TDClient/60/Portal/KB/ArticleDet?ID=4698)). Звонящие по телефону попадают в одну общую дорожку.

Через перехват звука процесса (как пишет Mostik) раздельных каналов нет: Zoom выводит уже смешанный звук.

Плюсы: разметка без ошибок, без диаризации. Mostik мог бы импортировать такую папку как встречу.
Минусы: запись идёт средствами Zoom — все участники видят значок записи; локальную запись может вести организатор или тот, кому он разрешил; файлы появляются только после конца встречи.

### 4. Встроенные расшифровки платформ — импорт, а не своя разметка

- **Телемост** для бизнеса сам делает расшифровку с подписью имён и конспект, присылает на почту организатору или участникам ([новость Яндекса](https://yandex.ru/company/news/02-16-04-2025), [опыт Яндекс 360](https://360.yandex.com/blog/guides/kak-effektivno-podvodit-itogi-vstrechi-v-telemoste-opyt-rukovoditelya-produktovoj-razrabotki-yandeks-360/)). Только корпоративные тарифы; запускается кнопкой во встрече, участники видят, что идёт запись. Как использовать: сопоставить его реплики с именами по времени и тексту с нашей расшифровкой и перенести имена на метки диаризации.
- **Google Meet в браузере**: субтитры Meet в DOM подписаны именем говорящего; так работают Tactiq и открытый [gMeetTranscriptCapture](https://github.com/Manuel02371/gMeetTranscriptCapture) ([Tactiq](https://tactiq.io/transcribe/google-meet)). Требует своего расширения Chrome и ломается при обновлении Meet. Для нас — только имена по времени, текст остаётся свой.

### 5. Слабые подсказки — для выбора, не для разметки

- Список участников из календаря сужает выбор для OCR и для подсказок голосовой памяти.
- Обращения в тексте («Петя, что скажешь?») — ИИ встречи может предложить имя, но только как подсказку с подтверждением.

## Как метка становится именем (общая часть для 1–4)

Источник даёт временную ленту «с t1 по t2 говорил X». Для каждой метки диаризации считаем, сколько её речи пришлось на интервалы каждого имени. Имя ставится, если одно имя набирает явное большинство (например ≥70% речи метки и ≥8 с) — как правило «доминирует» у meeting-notes. Иначе — подсказка с выбором, как сейчас у M15. Названная метка пополняет голосовую память M14 (если она включена) — и следующая встреча, даже живая без Zoom, узнаётся по голосу.

## Рекомендация

1. **Zoom через Accessibility** — первым: путь подтверждён Granola и открытым кодом, разрешение уже есть, работает без записи экрана и без значка записи у участников.
2. **Телемост**: сначала снять дерево Accessibility на живом звонке. Есть имена и индикатор — тот же путь, что для Zoom. Нет — **OCR кадров** поверх готовых кадров окна.
3. **Сопоставление «лента имён → метки диаризации»** — общий модуль движка, от источника не зависит; на нём же — импорт расшифровки Телемоста и папки раздельных дорожек Zoom.
4. Meet-расширение и импорт Zoom-дорожек — позже, по спросу.

## Что проверить первым

- Дерево Accessibility Zoom 7.2 и Телемоста 3.0 во время звонка: где имена плиток, есть ли признак «говорит» и как часто он обновляется. Нужен живой звонок минимум с одним собеседником.
- Насколько индикатор Zoom отстаёт от речи: от этого зависит сдвиг при сопоставлении.

## Прототип: Zoom через Accessibility

Сделано, проверено тестами; на живом звонке не проверялось.

- **Наблюдатель** — `Sources/Mostik/CallSpeakerObserver.swift` (раньше — `ZoomSpeakerObserver.swift`). Запускается вместе с записью встречи, раз в 250 мс обходит дерево Accessibility окон Zoom (`us.zoom.xos`, до глубины 8 и 2500 элементов, таймаут запроса 0,2 с) и дописывает в папку встречи `speaker-timeline.jsonl` строку при каждой смене говорящего. Новый обход не начинается, пока не закончен прежний. Время — по часам встречи, как у пометок: паузы не идут. Без разрешения Accessibility молчит.
- **Разбор подписи плитки** — `Sources/MostikCore/ZoomSpeakers.swift`: имя до первой запятой, дальше — состояние звука и «active speaker»; «(Me)»/«(Я)» — своя плитка, роли в скобках отбрасываются. Английские строки подтверждены чужим кодом, **русские — догадка**, проверить на звонке.
- **Сопоставление** — `engine/mostik_engine/speaker_timeline.py`, вызывается из `meeting.py` после диаризации. Отрезок имени начинается на 0,6 с раньше снимка (индикатор запаздывает), снимок действует до следующего и не дольше 30 с. Двое разом и своё имя — не в счёт. Имя ставится на метку, если под ним ≥4 с её речи, это ≥50% речи метки и вдвое больше, чем под вторым именем. Результат — в `speaker_names` (как ручное переименование, правится в окне встречи) и в `speaker_timeline` с долей и источником. Имя из ленты главнее имени из календаря.

### Что сделать на звонке

1. Поставить свежую сборку в `/Applications`.
2. Включить снятие дерева: `defaults write app.mostik.mac axDump -bool true`.
3. Созвон в Zoom (лучше в русском интерфейсе) и, отдельно, в Телемосте, минимум с одним собеседником; записать встречу в Mostik не меньше 2,5 минут, по очереди поговорить.
4. В папке встречи появятся `ax-dump-zoom-20.txt`, `-60`, `-120` (и `ax-dump-telemost-*.txt`) — в первой строке Zoom-снимка: какие плитки нашёл наблюдатель и сколько стоил обход. Плюс `speaker-timeline.jsonl`.
5. Выключить: `defaults delete app.mostik.mac axDump`. В снимках — имена участников, они не покидают Mac.

По снимкам: поправить маркеры русского Zoom, проверить, укладывается ли обход в 250 мс (если нет — запоминать контейнер плиток и обходить только его), и решить, есть ли путь у Телемоста.

### Первый звонок (Zoom 7.2.2, английский интерфейс)

- Плитки найдены, обход дерева — **~120 мс** (в 250 мс укладывается).
- Подпись плитки: `Alex Morgan, Computer audio muted, Video off` / `… unmuted …`. **Пометки «active speaker» в галерее с выключенным видео не было ни разу** за всю запись — имя не поставилось.
- «(Me)» в подписи нет. Свой микрофон виден по кнопке панели `id="audio"`: `Unmute my audio` — выключен, `Mute my audio` — включён.
- Телемост 3.0.9: в дереве только строка меню, окон нет.

Что изменено после звонка:

- Своя плитка — та единственная, чей микрофон совпадает с моим (работает и при одинаковых именах — один человек с двух устройств).
- Запасной признак: нет пометки «говорит» — говорит единственный собеседник с открытым микрофоном (в ленте поле `unmuted`). Двое с открытым микрофоном — имени нет.
- С `axDump` наблюдатель пишет `ax-tiles.jsonl` — все смены подписей плиток за звонок; снимки дерева — на 15-й, 40-й и 90-й секунде, без строки меню.

Следующий звонок: Zoom в режиме **Speaker view** (есть ли «active speaker»), звонок втроём с открытыми микрофонами; Телемост — с открытым окном звонка.

### Второй звонок (двое)

- Имени не было по двум причинам. Собеседница говорила 3,7 с — меньше порога `MIN_SECONDS`.
  К тому же всё это время её плитка в дереве значилась «muted»: Zoom обновляет подписи
  плиток с опозданием, у меня — на 1–1,5 с позже кнопки. По микрофону своей плиткой на
  миг оказалась чужая.
- Кнопка своего микрофона исчезает, когда Zoom прячет панель.
- Что изменено:
  - своё имя запоминается, если я один в звонке больше 5 с и микрофон плитки совпадает
    с кнопкой. Дальше своя плитка находится по имени, микрофон — последний признак;
  - в ленту пишется `present` — состав окна;
  - движок называет единственного собеседника по составу (`roster_name`, источник
    `zoom:roster`): один голос на системной дорожке и один человек в окне, кроме меня.
- Повтор на этой записи: «Собеседник 1» → имя собеседницы.
- Признак «микрофон открыт» годится только для длинной речи. Для групповых звонков нужна
  пометка «говорит» (вид «Speaker», не галерея) или кадры окна.

### Третий звонок (двое)

- Новая сборка сработала: своё имя узнано через 5 с, собеседница названа по ленте (33,5 с, 89%).
- Диаризация отнесла четыре коротких куска речи собеседницы на стыках реплик (по 1–2 с,
  вместе 13%) ко второй метке. Теперь один на один мелкие метки (вместе не больше
  `ROSTER_MINOR_SHARE` = 25% речи) получают то же имя. Если у второй метки доля
  больше, имя ей не ставится: возможно, это второй человек у того же микрофона.

## Телемост, Google Meet и другие ВКС

Вопрос: можно ли узнавать говорящих не только в Zoom — по каналу звука или по другим признакам. Короткий ответ: по каналу — почти нигде, по интерфейсу — да, и у Телемоста путь ближе, чем казалось.

### По каналу звука: раздельных дорожек нет

Перехват звука процесса (process tap) получает то, что приложение уже смешало для динамиков. Ни Zoom, ни Телемост, ни Meet не выводят участников разными каналами. Раздельные потоки бывают только внутри самого звонка, и добраться до них можно так:

| Где | Что есть | Цена |
|---|---|---|
| Zoom, локальная запись | файл на участника, имя в имени файла (§3 выше) | значок записи у всех, только после встречи |
| Zoom RTMS | звук каждого участника по WebSocket ([docs](https://developers.zoom.us/docs/rtms/meetings/media/)) | приложение Zoom Marketplace, согласие организатора |
| Google Meet в браузере | 3 «виртуальных» потока самых громких, настоящий источник — CSRC в RTP, постоянен на участника ([virtual streams](https://developers.google.com/workspace/meet/media-api/guides/virtual-streams)); `getContributingSources()` отдаёт CSRC с уровнем громкости | расширение браузера; имени в CSRC нет, его даёт корреляция с плиткой ([Volume-Individual](https://github.com/devgabe1/Volume-Individual-para-Google-Meet)) |
| Meet Media API | CSRC → участник прямо в протоколе (`MediaEntry.audioCsrc`) | Developer Preview, новые заявки закрыты, все участники должны быть в программе — для публичного приложения закрыто |
| Телемост (веб) | звук приходит слотами SFU, все голоса в одной смешанной дорожке, `audioLevel` нет ([разведка Vexa](https://github.com/Vexa-ai/vexa/pull/1735)) | по звуку не разделить |
| Teams | несмешанный звук только у бота Graph с application-hosted media | бот во встрече |
| Discord, Telegram | отдельный поток на пользователя (Craig, SSRC в групповых звонках) | бот или свой клиент |

Вывод: «по каналу» — не наш путь для локального приложения без ботов. Исключение — пространственный звук (Teams, VK Teams собран с `QtSpatialAudio`): если приложение раскладывает голоса по стерео, баланс левый/правый в дорожке системы совпадает с местом плитки. Это **догадка**, не проверялась; стоит одного замера, если дорожка пишется в стерео.

### Телемост: интерфейс звонка — веб-страница внутри приложения

Проверено по бандлу Телемоста 3.0.13 и по снимкам дерева Mostik:

- Десктопный клиент — **Qt 6 + QtWebEngine** (встроенный Chromium: `libQt6WebEngineCore`, `QtWebEngineProcess.app`). В снимке дерева окно звонка — пустая группа `…WebView::FrameQWebEngine…` размером 0×0: виджеты Qt видны, веб-содержимое — нет. Поэтому раньше «окон не было».
- Сборка QtWebEngine понимает переменные `QTWEBENGINE_CHROMIUM_FLAGS` (в строках есть `force-renderer-accessibility`) и `QTWEBENGINE_REMOTE_DEBUGGING`. Hardened runtime у приложения есть, но переменные окружения ему не мешают.
- Веб-клиент тот же, что на telemost.yandex.ru. По разведке Vexa (Playwright, живой звонок): звонок рисуется в iframe `/private-join/<id>`, у говорящего обводка плитки `rootStroke_*`, имя — на плитке; в узком окне при показе экрана полосы плиток нет. 21 реплика из 21 получила имя в раскладке «сетка». Ещё точнее — сообщения медиадвижка по WebSocket: в составе звонка у каждого участника `sendAudio`, в `slotsConfig` — `vad` по слотам; совпадает с обводкой посекундно и опережает её примерно на 1 с.

Отсюда три пути, от простого к точному:

1. **Accessibility веб-содержимого.** Попробовать выставить `AXManualAccessibility` / `AXEnhancedUserInterface` на процессе Телемоста (как для Chromium); не поможет — запускать Телемост с `QTWEBENGINE_CHROMIUM_FLAGS=--force-renderer-accessibility`. Тогда плитки с именами и обводкой попадают в то же дерево, которое Mostik уже обходит для Zoom. Порт не открывается, данные не уходят из Mac. Минус второго варианта: Телемост надо перезапустить из Mostik, если он уже открыт.
2. **Отладочный порт Chromium** (`QTWEBENGINE_REMOTE_DEBUGGING=127.0.0.1:<порт>`). Через DevTools Protocol видны DOM и кадры WebSocket — то есть `vad` медиадвижка, самый точный сигнал. Минус серьёзный: пока порт открыт, любой локальный процесс управляет залогиненным Телемостом. Для публичной сборки — только как опция «для разработчика», выключенная по умолчанию.
3. **Веб-версия в браузере** — те же признаки через Accessibility Chromium (`AXManualAccessibility` на процессе браузера) или через расширение. Годится, если человек звонит из браузера.

Встроенный конспект Телемоста (Алиса в Яндекс 360 для бизнеса) приходит письмом организатору до 24 часов, через API не настраивается и не выгружается; подписывает ли он реплики именами, официально не подтверждено ([справка](https://yandex.ru/support/yandex-360/business/telemost/web/ru/summary)). API Телемоста (`cloud-api.yandex.net/v1/telemost-api/conferences`) умеет создать встречу, прочитать и изменить её; участников и «кто говорит» в нём нет ([документация](https://yandex.ru/dev/telemost/doc/ru/)). Живые субтитры в официальной справке не описаны.

### Google Meet (в браузере)

- **Accessibility Chromium без расширения.** Chromium строит дерево страницы лениво: нужно выставить `AXManualAccessibility` на процессе браузера и перечитать через ~150 мс ([Chromium](https://chromium.googlesource.com/chromium/src/+/main/docs/accessibility/overview.md)). Открытый [seashell, PR #33](https://github.com/stupart/seashell/pull/33) так и читает плитку говорящего в Chrome; Safari там не поддержан. Granola и Recall Desktop SDK заявляют имена говорящих для Meet без бота ([Granola](https://docs.granola.ai/help-center/taking-notes/speaker-attribution), [Recall](https://docs.recall.ai/docs/desktop-sdk)).
- **Субтитры Meet** подписаны именем: регион `[role="region"][aria-label="Captions"]` — его читают открытые расширения ([google-meet-transcriber](https://github.com/teja119/google-meet-transcriber), [gMeetTranscriptCapture](https://github.com/vincelamm/gMeetTranscriptCapture)). Через Accessibility он виден так же, как плитки, если человек включил CC. Текст берём свой, из субтитров — только «кто и когда».
- **После встречи** (Workspace, включена расшифровка): REST API `conferenceRecords.transcripts.entries` — у каждой реплики `participant` и `startTime`, хранится 30 дней ([artifacts](https://developers.google.com/workspace/meet/api/guides/artifacts)). Подходит для сверки: выровнять реплики по времени и тексту с нашей расшифровкой и перенести имена на метки — тот же модуль, что для ленты Zoom.

## Наблюдатель для Телемоста и Meet

Сделано и проверено тестами на синтетических деревьях. На живом звонке не проверялось.

- **Источник — приложение с микрофоном.** `CallSpeakerObserver` раз в 2 с спрашивает `MeetingDetector.currentMeetingBundleID()`, кто держит микрофон, и выбирает, что читать:
  - Zoom — как раньше, подписи плиток;
  - Телемост — все его окна (звонок — веб-страница во встроенном Chromium);
  - Chromium-браузер (Chrome, Яндекс Браузер, Arc, Edge, Brave, Opera, Vivaldi) — только окно, чей заголовок похож на звонок: `Meet - …` или «Телемост». Другие окна и вкладки не читаются.
  Safari и Firefox пока не поддержаны: у них в дереве нет DOM-классов. Сменилось приложение — прежний источник закрывается тишиной.
- **Веб-доступность.** Процессу Телемоста и браузера один раз выставляется `AXManualAccessibility`: без него Chromium не строит дерево страницы.
- **Разбор** — `Sources/MostikCore/WebCallSpeakers.swift`, по DOM-классам из `AXDOMClassList`.
  - **Meet** — по устройству дерева с реального звонка в Chrome (открытый [seashell](https://github.com/stupart/seashell), MIT, сентябрь 2026):
    - плитка — группа `oZRSLe`;
    - имя — единственный текст в подписи `XEazBc adnwBd`;
    - говорит — значок `DYfzY cYKTje` с одним из классов `Oaajhc`, `HX2H7`, `wEsLMd`, `OgVli`.
    Значок «говорит» вне разобранной плитки — никого не называем. Своя плитка — по пометке «(You)» / «(Вы)» в открытой панели «Участники». Классы Meet генерируются сборкой и меняются с обновлениями.
  - **Телемост** — догадка по разведке Vexa: говорящий — элемент с классом `rootStroke_*`, имя — текст ближайшего предка с текстом, не выше четырёх уровней. Остальных участников без снимка не видно.
- В ленте `speaker-timeline.jsonl` источник — `meet` или `telemost`. Движок источник не различает: сопоставление с метками диаризации то же, что у Zoom.
- **Снимок дерева** (`axDump`) пишет и DOM-классы (`class="…"`), и DOM-id (`dom="…"`). Снимаются Zoom, Телемост и окна браузеров со звонком: `ax-dump-zoom-*`, `ax-dump-telemost-*`, `ax-dump-meet-web-*`, `ax-dump-telemost-web-*`. В первой строке — что разобрал наблюдатель и сколько занял обход.

Обход страницы ограничен 5000 элементами и глубиной 45. Если он дольше 250 мс, следующий просто ждёт. Насколько это тормозит, видно по первой строке снимка.

### Что сделать на звонке

1. Свежая сборка в `/Applications`, включён `axDump` (`defaults write app.mostik.mac axDump -bool true`).
2. **Телемост, десктоп.** Созвон хотя бы с одним собеседником, запись в Mostik не меньше 2 минут, говорить по очереди. Посмотреть `ax-dump-telemost-40.txt`:
   - есть `AXWebArea` с плитками и `class="…"` — дерево открыто, ищем в нём `rootStroke` и имена;
   - вместо страницы пустая группа `FrameQWebEngine` 0×0 — одного флага мало. Закрыть Телемост и запустить так: `open --env QTWEBENGINE_CHROMIUM_FLAGS=--force-renderer-accessibility /Applications/Yandex.Telemost.app`. Повторить звонок.
3. **Телемост в браузере** — тот же звонок во вкладке Chrome или Яндекс Браузера: `ax-dump-telemost-web-*.txt`.
4. **Meet в Chrome** — созвон, у себя выключить микрофон или открыть панель «Участники». Проверить, что в `ax-dump-meet-web-*.txt` есть `oZRSLe` и в первой строке названы плитки и `[active]`.
5. Выключить: `defaults delete app.mostik.mac axDump`. В снимках — имена участников, у Телемоста может попасть и текст открытых чатов. Снимки не покидают Mac.

По снимкам: подтвердить или заменить признак `rootStroke` у Телемоста, найти признак своей плитки, сверить классы Meet.
