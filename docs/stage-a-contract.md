# Этап A: договор между приложением и движком

Словарь из контекста, правила речи и встречи. Папку проекта не выбирают вручную: она определяется сама.

Общие типы уже лежат в коде: `MostikSettings` (`autoProject`, `extraSources`, `calendarEnabled`, `consentAcknowledged`, `handsFreeDoubleTap`), `HistoryEntry.rawText`, в `AppModel` — `SourceItem`, `TermItem`, `MeetingMark`, свойства `sources`, `terms`, `sourcesScanning`, `currentProject`, `meetingMarks`, `meetingPaused`, `meetingConsentPending` и намерения `onRescanSources`, `onAddSource`, `onRemoveSource`, `onSetCalendarEnabled`, `onAddMeetingMark`, `onToggleMeetingPause`, `onAcknowledgeConsent`. Менять их сигнатуры нельзя — только добавлять.

## Протокол движка (JSON lines)

Виды терминов: `person`, `project`, `tech`, `acronym`, `identifier`.

Происхождение термина (`origins`): `"<относительный путь>:<строка>"` для файлов, `"календарь: <название встречи>"`, `"личный словарь"`.

| Команда | Поля | Ответ |
|---|---|---|
| `start`, `transcribe_file` | как раньше + `sources`: `[путь, …]` — папки документов (необязательно) | как раньше. Словарь сессии = проект + `sources` + календарь + личный |
| `calendar` | `events`: `[{id, title, start, end, attendees: [имя, …], notes}]` (ISO 8601) | `{ok, events, terms}`. Берутся события с ≥2 участниками; хранятся в `<home>/calendar.json` и заменяют прошлый набор целиком |
| `sources` | `project` (путь или null), `sources` (список путей) | `{ok, sources: [{kind, label, path, scanned_at, counts: {вид: n}, total}], terms: [{term, kind, origins, in}]}`; `kind` ∈ `repo`, `docs`, `calendar`, `personal`; терминов не больше 5000. `in` — список значений `path` источников, где нашёлся термин (для фильтра в интерфейсе); у календаря `path` = `"calendar"`, у личного словаря — `"personal"`, у папок — путь как его прислало приложение |
| `rescan` | как у `sources` | то же, но с пересканированием, без кэша |
| `meeting` | как раньше + `marks: [{at, text}]` (секунды от начала), `title`, `attendees: [имя, …]` | как раньше |

Кэш словаря проекта с происхождением — `<home>/projects/<sha1 корня>.json`: `{root, scanned_at, terms: [{term, kind, origins}]}`. Повторное сканирование не чаще раза в 10 минут, если не пришёл `rescan`.

Уточнения движка, сделанные по ходу реализации:

- `calendar`: в ответе `events` — число принятых событий (с ≥2 участниками), `terms` — `[{term, kind, origins}]`, ближайшие к текущему моменту встречи первыми.
- `meeting.attendees`: элемент — строка-имя или `{name, self}`, где `self: true` у владельца календаря (`EKParticipant.isCurrentUser`); есть и необязательное поле `owner` (имя владельца). Без пометки владельца список из двух имён двусмысленный, и имя собеседнику не подставляется.
- `sources`/`rescan`: у карточки источника могут быть дополнительные поля `files`, `truncated` (упёрлись в лимит 2000 файлов или 20 МБ текста), `events` (у календаря), `error` (папки нет — тогда `total` = 0).
- Кэш: в основном файле, кроме полей договора, есть `version`, `kind`, `scanned_ts`, `files_count`, `truncated`, `counts`; данные по каждому файлу для повторного обхода лежат рядом, в `<sha1 корня>.files.json`, чтобы старт сессии читал маленький файл.
- `start` не ждёт обход дольше 200 мс: дальше обход идёт в фоне, сессия берёт прошлый результат из памяти или кэша, свежий подхватит следующая сессия.
- Корень `project` может быть рабочей папкой агента, а не репозиторием: обход в ширину (ближние к корню файлы первыми, на уровне — свежие папки первыми), пропуск `06_archive`, `drafts`, `.worktrees`, `.claude` и всего скрытого, папок данных (от 20 файлов, ≥80 % — `.json`, `.csv`, картинки, звук).
- Извлечение (отступления от раздела «Правила извлечения» ниже): аббревиатуры из 2 заглавных (кроме `OK`, `ID`, единиц вроде `ГБ`) и пары «буква + цифра» (`S3`) берутся, хотя короче 3 символов; хэш — ≥7 шестнадцатеричных с цифрой или ≥12 без неё (иначе гибнут слова вроде `defaced`); латинское слово в тексте, где кириллицы больше, и в заголовке Markdown — термин вида `tech`; заглавная сразу после открывающей кавычки — начало цитаты, не имя («Словарь», «Записать» — подписи интерфейса); в репозитории все `.md` идут по правилам документов. Частотного списка в transcriber нет, сеть не используем — словарные слова берутся из встроенных списков `engine/mostik_engine/wordlists.py` (частые английские и русские слова плюс служебные имена кода).

## Правила извлечения

Берём: идентификаторы из кода (их Eloquent выбрасывает, мы — нет, это наша ниша), CamelCase и snake_case, аббревиатуры из 2–6 заглавных букв, слова с латиницей и цифрами (`GPT4o`, `S3`), имена собственные — слово с заглавной не в начале предложения, повторённое хотя бы дважды, — кодовые имена (слово после «проект», «клиент», «project», «codename»), заголовки Markdown.

Выбрасываем: словарные слова (частотный список языка), числа и версии (`1.2.3`, `v2`), хэши (≥7 шестнадцатеричных символов), почту, логины (`@user`), URL, пути, слова короче 3 символов.

Документы: `.md`, `.markdown`, `.txt`, `.pdf` (текст через `pdftotext`, если он есть в системе, иначе пропуск), заметки Obsidian — это те же `.md`. Пропускаем `.git`, `node_modules`, `.venv`, `.obsidian`, `dist`, `build` и всё скрытое. Не больше 2000 файлов и 20 МБ текста на источник.

## Встречи

- Метки ложатся в `transcript.md` строкой `> 📌 MM:SS — текст` перед первой репликой, которая начинается не раньше метки. В `transcript.json` — поле `marks`.
- Говорящие: дорожка микрофона — всегда «Я»; системная — «Собеседник N» по диаризации. Имя из календаря подставляется только если внешний говорящий один, а участник, кроме владельца календаря, тоже один. Имена из текста речи не берём никогда. Слово «микрофон» или «система» как говорящий в выводе не появляется.

## Приложение

- **Автопроект.** Когда начинается диктовка и впереди терминал, Cursor или VS Code: найти процесс `claude` или `codex` в дереве процессов этого приложения, взять его рабочую папку (`proc_pidinfo` с `PROC_PIDVNODEPATHINFO`), подняться до корня git; нет git — сама рабочая папка (кроме домашней и корня диска): агент может быть запущен из общей рабочей папки, которая не репозиторий. Не нашли агента — `settings.projectPath`. Результат идёт в `start.project` и в `AppModel.currentProject`. Кэш по PID.
- **Календарь.** EventKit, полный доступ на чтение (`NSCalendarsFullAccessUsageDescription`). Только после включения пользователем (`calendarEnabled`); события на ±7 дней; отправка `calendar` при включении, на старте и раз в час. При записи встречи текущее событие (идёт сейчас, ±10 минут) даёт `title` и `attendees`.
- **Без рук.** Двойное нажатие клавиши диктовки (два нажатия короче 0,3 с с паузой не больше 0,4 с) начинает запись без удержания; следующее одиночное нажатие останавливает. Через `DictationMachine` (`togglePressed`) с тестами.
- **Две версии.** `final.raw_text` → `HistoryEntry.rawText`. В «Диктовке» у записи две версии: «как сказано» и «как вставлено», у каждой кнопка «Копировать». Если обработка упала, вставляется сырой текст.
- **Источники.** Раздел во вкладке «Словарь»: карточки источников со счётчиками по видам, «просканировано N ч назад · Пересканировать», «Добавить папку», переключатель календаря, поиск по терминам с происхождением.
- **Встречи.** Пилюля записи встречи вместо обычного HUD: «● Live», таймер, волна, пауза, развернуть. В развёрнутом виде — поле короткой пометки (Enter добавляет с текущим временем). Перед первой записью — предупреждение о согласии участников (`consentAcknowledged`), в онбординге — та же строка. Звукового напоминания нет.
- **Онбординг.** Шаг выбора папки проекта убран. Ручная замена остаётся в «Источниках».
