# Календари

Mostik берёт из календаря названия встреч, участников, ссылку на звонок и время: для напоминания за минуту, имени встречи, справки перед ней и словаря распознавания. Источник выбирается в «Настройки → Встречи → Календарь». По умолчанию не подключён ни один, и Mostik ничего не читает, пока вы не выберете.

| Источник | Как подключается | Что хранится | Куда ходит Mostik |
|---|---|---|---|
| Google Календарь | вход в браузере, только чтение | ключ обновления доступа — в связке ключей; почта и отмеченные календари — в `settings.json` | `accounts.google.com`, `oauth2.googleapis.com`, `www.googleapis.com` |
| Яндекс Календарь | логин и пароль приложения, CalDAV | пароль приложения — в связке ключей; логин и отмеченные календари — в `settings.json` | `caldav.yandex.ru` |
| Календарь macOS | разрешение «Календари» и выбор календарей | идентификаторы отмеченных календарей — в `settings.json` | никуда: события читаются с этого Mac |
| Команда календаря | «Ещё → Команда календаря», свой файл | путь — в `settings.json`, отпечаток — в связке ключей | куда ходит ваша команда ([external-calendar.md](external-calendar.md)) |

У каждого подключённого источника есть «Календари…»: Mostik читает только отмеченные. При первом подключении отмечен основной календарь аккаунта. События запрашиваются раз в 5 минут за ±7 дней от текущего момента; ошибка сети не стирает прежние события, а строка источника в Настройках показывает «ошибка: …». Если вход больше не принимается (пароль приложения удалён, доступ Google отозван), строка пишет «Нужно подключить заново».

Одна встреча в двух источниках показывается один раз: дубли ищутся по названию без учёта регистра и минуте начала, остаётся версия Календаря macOS, потом Google, потом Яндекса, потом команды.

Событие на весь день, отменённое событие и встреча, от которой вы отказались, не считаются встречами. Встреча — это событие хотя бы с двумя участниками; переговорки и ресурсы участниками не считаются.

## Google

«Подключить…» открывает страницу входа Google в браузере. Mostik просит два разрешения: чтение календаря (`calendar.readonly`) и почту аккаунта, чтобы показать в Настройках, какой аккаунт подключён. Вход идёт по схеме для установленных приложений (RFC 8252): PKCE S256, ответ приходит на `127.0.0.1` со случайным портом, приёмник слушает только этот адрес и закрывается сразу после ответа или через 5 минут.

Mostik хранит только ключ обновления доступа (refresh token) — в связке «Вход», с доступом только для Mostik. Ключ доступа на час живёт в памяти. «Отключить» отзывает ключ у Google и удаляет его из связки.

Повторы разворачивает сам Google (`singleEvents=true`).

### Сборка с Google

OAuth-клиента в репозитории нет. Чтобы Google работал в своей сборке:

1. В Google Cloud Console создайте проект, включите Google Calendar API.
2. Настройте экран согласия OAuth: тип «External», разрешения `calendar.readonly`, `openid`, `email`.
3. Создайте учётные данные OAuth client ID с типом «Desktop app».
4. Соберите приложение с переменными окружения:

   ```bash
   MOSTIK_GOOGLE_CLIENT_ID=… MOSTIK_GOOGLE_CLIENT_SECRET=… scripts/bundle.sh
   ```

   `bundle.sh` впишет их в `Info.plist` (`MostikGoogleClientID`, `MostikGoogleClientSecret`). Секрет клиента типа «Desktop app» по правилам Google не секретен (RFC 8252 §8.5), но в репозиторий его всё равно не кладём: он привязан к вашему проекту в Google Cloud.

Без `MOSTIK_GOOGLE_CLIENT_ID` строка Google в Настройках пишет «Недоступно в этой сборке».

Пока приложение в Google Cloud в статусе «Testing», войти могут только тестовые пользователи, которых вы добавили, и доступ истекает через 7 дней. Для публичной сборки приложение нужно опубликовать и пройти проверку Google для чувствительного разрешения `calendar.readonly`.

## Яндекс

Яндекс Календарь подключается по CalDAV к `https://caldav.yandex.ru`. Пароль от аккаунта не подойдёт, нужен пароль приложения: id.yandex.ru → Безопасность → Пароли приложений → Календарь CalDAV.

При подключении Mostik находит календари аккаунта (PROPFIND: `current-user-principal`, `calendar-home-set`, список коллекций) и показывает только календари с событиями — без дел и напоминаний. События берутся запросом `calendar-query` с окном дат; повторы (RRULE, EXDATE, перенесённые экземпляры) разворачиваются на Mac.

Пароль и логин уходят только на `caldav.yandex.ru` и только по https: если сервер в ответе указывает на другой адрес, Mostik туда не идёт и показывает ошибку. Пароль хранится в связке «Вход», с доступом только для Mostik. «Отключить» удаляет его.

Тот же код подходит для любого сервера CalDAV, но в Настройках сейчас только Яндекс.

## Календарь macOS

«Выбрать…» запрашивает разрешение «Календари» и показывает все календари этого Mac: iCloud, Exchange и другие аккаунты из «Системные настройки → Интернет-аккаунты». Mostik читает только отмеченные, без сети.

До этой версии Mostik читал все календари macOS, если был включён переключатель «Календарь». Теперь сами они не подключаются: после обновления календари macOS нужно выбрать заново.

---

**English.** Settings → Meetings → Calendar offers Google Calendar (browser sign-in, PKCE, loopback `127.0.0.1`, read-only scope), Yandex Calendar (CalDAV at `caldav.yandex.ru` with an app password) and the macOS Calendar (only the calendars you tick). None is connected by default. Each source has a calendar picker; events are fetched every 5 minutes for ±7 days, duplicates across sources are merged. The Google refresh token and the Yandex app password live in the login keychain with Mostik-only access; `settings.json` keeps only the login and the ticked calendars. Builds get Google only when `MOSTIK_GOOGLE_CLIENT_ID` (and `MOSTIK_GOOGLE_CLIENT_SECRET` for a Desktop-app client) are set for `scripts/bundle.sh`. After updating, macOS calendars must be picked again.
