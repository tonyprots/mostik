# Архив встреч без векторов

Архив собирается из папок встреч (контракт — `meeting-folder.md`) обычными файлами Markdown, без векторного индекса. Панели архива в окне приложения сейчас нет: архив — это файлы в папке данных и инструменты MCP для агентов (`get_meeting_card`, `get_person`, `get_brief`, `get_digest`, `track_topics`). Код движка: `engine/mostik_engine/archive.py`, `archive_service.py`, `due_dates.py`, `task_state.py`. Приложение: `Sources/MostikCore/Archive.swift` и расписание в `Sources/Mostik/ArchiveController.swift`.

## Что где лежит

Всё в `~/Library/Application Support/Mostik/`:

| Путь | Что это | Кто пишет |
|---|---|---|
| `meetings/<id>/card.md` | Карточка встречи: решения, открытые вопросы, поручения, люди, цитаты. У каждого пункта ссылка `<id>/transcript.md:<строка>` | движок, раз в час |
| `people/<имя>.md` | Карточка человека: все встречи, его обещания, ваши обещания ему, последний разговор, ближайшие встречи из календаря, есть ли голос в голосовой памяти | движок, раз в час |
| `briefs/<YYYY-MM-DD-HHMM>-<название>.md` | Бриф к встрече | приложение за 10 минут до встречи |
| `digests/week-YYYY-Www.md`, `digests/series-<хэш>.md` | Сводка за неделю и по серии | приложение по расписанию (неделя) |
| `archive/tasks.json` | Отметки поручений «сделано» и «не будет» | в этой версии никто: файл только читается, если остался |

В шапке карточки встречи записаны `card_version`, `prompt_version` (сейчас `rules-1`) и отпечаток исходных файлов. Если поменялись правила или исходники, карточка считается устаревшей и пересобирается. Карточка собирается правилами, без модели, поэтому её можно перепроверить.

Раздел `## Мои заметки` в карточке человека принадлежит пользователю: при пересборке он сохраняется. Если человек пропал из видимых встреч, например все встречи с ним стали чувствительными, его файл заменяется заглушкой «Видимых встреч нет». Так старое содержимое не остаётся лежать на диске.

## Чувствительные встречи

Встречи с `sensitive: true` не попадают в карточки людей, брифы, сводки, ответы агента архива, CLI и MCP. Для них не пишется `card.md`. Исключение одно — собственный просмотр тем с флагом `include_sensitive`: результат видит только сам пользователь, и наружу он не уходит.

## Бриф и поручения

За 10 минут до встречи из календаря (событие с двумя участниками и больше) приложение собирает бриф из двух-трёх пунктов:

- на чём остановились в прошлый раз;
- открытые обещания: вся серия целиком, а вне серии — только обещания участников этой встречи и ваши;
- о чём договорились.

Бриф сохраняется файлом в `briefs/` и отдаётся агентам через MCP (`get_brief`).

Серия — это одно повторяющееся событие календаря (`cal:<id события без @время>`). Если календаря нет, серией считается одно и то же название у двух встреч и больше (`title:<название>`).

Срок поручения достаётся из речи детерминированно (`due_dates.py`, 61 тест), по-русски и по-английски:

- «до пятницы» — ближайшая пятница после встречи;
- «к следующему вторнику» — вторник следующей недели;
- «к концу недели», «на следующей неделе», «до конца месяца», «в конце квартала»;
- «через 3 дня»;
- явные даты.

Просрочка считается от сегодняшнего дня.

## Сводки и темы

Сводка за неделю собирается сама в выбранный день и час: по умолчанию пятница, 17:00. Расписание работает внутри приложения, без launchd. Если приложение было закрыто, сводка соберётся при следующем запуске на той же неделе. Сводку по серии отдаёт CLI (`mostik digest series <ключ>`) и MCP (`get_digest`). В сводке темы, решения и открытые поручения.

Слова-триггеры передаются в запросе: `mostik topics <слова…>` или MCP `track_topics`. Совпадение ищется по основе слова, а фраза из нескольких слов должна идти подряд. В ответе видно, на каких встречах и кто сказал, со ссылкой на строку расшифровки.

## Протокол движка

| Команда | Поля | Ответ |
|---|---|---|
| `archive_brief` | `event{id, title, start, attendees}` или `event_id`, или `within_minutes`; `write` | `{brief \| null, path}` |
| `archive_people` | `write` | `{items, written?}` |
| `archive_digest` | `kind: week \| series`, `series`, `days`, `write` | `{digest, path}` |
| `archive_cards` | `force` | `{written, fresh, skipped}` |

Поле `action_items` в `meetings get` и `meetings actions` теперь дополнено полями `key`, `due_date`, `status`.

## Агентам: CLI и MCP

Только чтение, чувствительные встречи не отдаются, на диск ничего не пишется (это проверяется тестом по хэшу дерева файлов):

```
mostik meetings card <id>
mostik people [имя]
mostik brief [--event-id ID] [--hours 24]
mostik series
mostik digest week|series [ключ] [--days 7]
mostik topics <слова…> [--days N] [--limit 20]
```

Инструменты MCP: `get_meeting_card`, `get_person`, `get_brief`, `get_digest`, `track_topics`.
