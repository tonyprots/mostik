# Папка встречи: контракт

Это формат для людей, скриптов (хук после встречи), CLI и MCP: кто читает встречи Mostik, читает их отсюда и по этим правилам.

Схемы JSON: `docs/schemas/meeting-manifest.schema.json`, `meeting-frontmatter.schema.json`, `meeting-transcript.schema.json`. Код: `engine/mostik_engine/meeting_folder.py` (движок), `Sources/MostikCore/MeetingFolder.swift` (приложение).

## Где лежит

`~/Library/Application Support/Mostik/meetings/<id>/`, где `<id>` — время начала записи `yyyy-MM-dd-HHmmss` по местному времени (у самых старых встреч — `yyyy-MM-dd-HHmm`). Одна папка — одна встреча. Папки, начинающиеся с точки, и папки без аудио, расшифровки и манифеста — не встречи.

## Файлы

| Файл | Кто пишет | Что внутри |
|---|---|---|
| `manifest.json` | приложение и движок | Машинное описание: название, время, участники, событие календаря, флаг `sensitive`, статусы записи, расшифровки и сводки, список файлов |
| `meeting.md` | движок (генерирует) | YAML-шапка + сводка, решения, поручения, ссылки на остальные файлы. Удобно класть в Obsidian |
| `transcript.json` | движок | Дословная расшифровка по говорящим, пометки, участники |
| `transcript.md` | движок | Та же расшифровка для чтения |
| `notes.md` | приложение, потом человек | Повестка из события, подготовка, пометки по ходу. Свои заметки пишите сюда — его не перегенерируем |
| `notes.json`, `summary.md` | движок, ИИ встреч | Сводка, заметки по пометкам, задачи со ссылками на реплики; в `notes.json` ещё разделы, решения, протокол и дополнительные виды |
| `summaries/<вид>.md` | движок | Дополнительные виды сводки: `protocol.md`, `exec.md`, `decisions.md`, `custom-<хэш>.md`. Основную не затирают |
| `history/` | движок | Прежние сводки перед пересборкой: `mode-<режим>-<время>.json`, `variant-<вид>-<время>.json`, `summary-<время>.md` |
| `recipes/<рецепт>-<время>.md` | движок | Черновики рецептов: письмо-итог, PRD, обратная связь, запросы на функции. Ничего не отправляется |
| `attachments/`, `*.ocr.txt` | приложение | Картинки к встрече и текст с них, распознанный на Mac; в `notes.md` — строка `![подпись](attachments/…)` в разделе «Картинки» |
| `next-steps/` | приложение | Черновики следующих шагов по кнопке: `tasks.md`, `follow-up.ics` |
| `mic.wav`, `system.wav` | приложение | Дорожки: микрофон («Я») и звук системы. 16 кГц, моно, PCM16 |
| `mic.2.wav`, `system.2.wav`, … | приложение | Новые сегменты после того, как дорожка вставала |
| `clips/` | приложение | Фрагменты для пересылки: `<начало>-<конец>.m4a` + `.md` |
| `questions.json` | движок | Вопросы, пойманные по ходу записи, и «отвечен / нет». Ниже — раздел «Вопросы встречи» |
| `frames/`, `frames/*.ocr.txt` | приложение | Кадры окна звонка `ЧЧММСС.jpg` по времени записи и текст с них, распознанный на Mac. Только по согласию на эту встречу |
| `meeting.edited-<время>.md` | движок | Ваша правка `meeting.md`, сохранённая перед перегенерацией |
| `system-transcript/speakers.json` | transcriber | Отрезки диаризации системной дорожки; по ним считается уверенность меток |
| `speaker-timeline.jsonl` | приложение | Лента говорящих из окна звонка (Zoom, Телемост, Meet): строка `{at, active, unmuted, present, self, source}` при каждой смене. По ней движок подписывает собеседников именами |
| `card.md` | движок | Карточка встречи для архива: участники, темы, решения, задачи. Перестраивается сама, править не нужно |
| `ax-tiles.jsonl`, `ax-dump-*.txt` | приложение | Только при отладочном `axDump` в `settings.json`: сырые подписи окна звонка для разбора ленты говорящих |

## manifest.json

```json
{
  "schema": "mostik.meeting",
  "version": 1,
  "id": "2026-10-11-153000",
  "title": "Синк по бюджету",
  "title_source": "calendar",
  "started": "2026-10-11T15:30:00+03:00",
  "ended": "2026-10-11T16:02:10+03:00",
  "duration_seconds": 1930.4,
  "language": "ru",
  "attendees": [{"name": "Анна", "self": true}, {"name": "Иван Петров", "self": false}],
  "calendar": {"event_id": "…@1760185800", "title": "Синк по бюджету",
               "start": "…", "end": "…", "link": "https://telemost.yandex.ru/j/…"},
  "sensitive": false,
  "app": "Телемост",
  "recording": {"status": "complete", "restarts": 0,
                "segments": [{"track": "mic", "file": "mic.wav", "offset_seconds": 0}], "warnings": []},
  "transcript": {"status": "done", "attempts": 1, "error": null},
  "summary": {"status": "done", "mode": "detailed"},
  "audio": {"kept": true, "trashed_at": null, "files": ["mic.wav", "system.wav"]},
  "files": {"meeting_md": "meeting.md", "transcript_json": "transcript.json", "notes_md": "notes.md"},
  "hook": {"ran_at": "…", "exit_code": 0, "timed_out": false, "skipped": null}
}
```

Статусы:

- `recording.restarts` — сколько раз сторож перезапускал дорожки, всего (целое). Разбивка по дорожкам — в `recording.restarts_by_track`: `{"mic": 1, "system": 0}`.
- `recording.status`: `recording` — запись идёт; если приложение не запущено, а статус `recording`, значит, оно упало посреди записи. `complete` — записано без сбоев. `recovered` — дорожка вставала, сторож перезапустил её новым сегментом. `incomplete` — часть звука потеряна (сторож сдался после 3 попыток или приложение упало).
- `transcript.status`: `pending` → `processing` → `done` или `failed`. `missing` — старая встреча без расшифровки, сама при запуске не дорасшифровывается.
- `summary.status`: `none`, `done`, `partial`, `failed`.
- `title_source`: `calendar` — из события, `default` — «Встреча 14:32», `summary` — тема из основной сводки (ставится только вместо `default` и обновляется при пересборке), `user` — введено человеком и не меняется.
- `transcript.code` при `done`: `diarization_unavailable` — на этом Mac нет `fluidaudiocli` или моделей голосов; `diarization_failed` — модель голосов дважды упала на этой записи. В обоих случаях системная дорожка расшифрована одним собеседником. При `failed`: `diarization_memory` — не хватило памяти, можно повторить без голосов.
- `audio.kept: false` — аудио перенесено в Корзину macOS после готовой сводки (настройка выключена по умолчанию). Восстанавливается из Корзины.

Запись — слиянием: прочитать, поменять свои ключи, записать во временный файл и переименовать. Неизвестные ключи сохранять.

## meeting.md

```markdown
---
id: "2026-10-11-153000"
title: "Синк по бюджету"
started: "2026-10-11T15:30:00+03:00"
ended: "2026-10-11T16:02:10+03:00"
duration_seconds: 1930.4
attendees:
  - "Анна"
  - "Иван Петров"
action_items:
  - assignee: "Иван Петров"
    task: "Подготовить смету"
    due: "до пятницы"
decisions:
  - "Решили перенести релиз на ноябрь"
sensitive: false
---

# Синк по бюджету
…
```

- Строки в шапке — в двойных кавычках JSON (это валидный YAML), пустые списки — `[]`, нет значения — `null`.
- `action_items` берутся из задач ИИ встречи: `assignee` — метка говорящего, имя из календаря или «группа»; `null` — исполнитель не прозвучал. `due` — срок как прозвучал.
- `decisions` — список решений, который модель возвращает вместе со сводкой (поле `decisions` того же ответа, отдельного вызова нет). Если списка нет (старая сводка), берутся пункты сводки, которые начинаются с «решили», «договорились», «согласовали», «утвердили» (или их английских аналогов).
- `meeting.md` перегенерируется после расшифровки, после ИИ встречи и при смене флага. Если вы правили файл, прежняя версия сохраняется рядом как `meeting.edited-<время>.md`. Строку `sensitive:` приложение правит само, это правкой не считается.

## Чувствительная встреча

**Правило для всех потребителей:** встреча чувствительная, если `manifest.json → sensitive == true` **или** в шапке `meeting.md` стоит `sensitive: true`. В Python — `meeting_folder.is_sensitive(folder)`; список без чувствительных — `meeting_folder.list_meetings(root)`.

Чувствительную встречу не получают:

- хук после встречи — не запускается, в манифест пишется `hook.skipped: "sensitive"`;
- рецепты после встречи — движок отвечает `status: "refused"` без вызова модели; следующие шаги в карточке выключены; брифы;
- MCP и CLI — не показывают в списке и не отдают по id без явного флага владельца.

Локальный поисковый индекс встречу по-прежнему видит.

Поставить флаг: переключатель «Чувствительная» в карточке встречи или `sensitive: true` в шапке `meeting.md` руками.

## Миграция старых встреч

При каждом запуске движка приложение шлёт `meetings_migrate`. Папке без манифеста движок добавляет `manifest.json`, `meeting.md` и, если были пометки, `notes.md`. Существующие файлы не переписываются и не удаляются. Встреча без расшифровки получает `transcript.status: missing` и сама не дорасшифровывается — только кнопкой. Повторный прогон ничего не меняет.

## Протокол движка

| Команда | Поля | Ответ |
|---|---|---|
| `meeting` | как раньше + `started`, `ended` (ISO), `calendar {event_id, title, start, end, link}`, `agenda: [строка]`, `sensitive`, `segments: {mic: [{file, offset_seconds}], system: […]}` | `meeting_done` + `meeting_md`, `manifest` |
| `meetings_migrate` | `root` (необязательно) | `{ok, scanned, migrated, errors}` |
| `meeting_question` | `folder`, `track` (`mic`/`system`), `at` (с), `text`, `speaker` (необязательно), `judge` (по умолчанию да) | `{questions, updated, judge}` — `questions` — новые вопросы, `updated` — закрытые ответом; `judge`: `{available, reason}`, `reason` — `off`, `not_loaded`, `memory`, `timeout` |
| `meeting_questions` | `folder` | `{items, counts}` — служебная: приложение её не зовёт, нужна для отладки и тестов |
| `meeting_questions_finalize` | `folder`, `close_pending` | `{items, counts}` — пересчёт «отвечен / нет» по готовой `transcript.json` с говорящими |
| `meeting_hint` | `folder`, `question`, `question_id`, `project`, `consent`, `answer` | Плоский ответ `{question, status, answer, answer_by, snippet, source, more, glossary, timings}`. `status`: `found` — есть фрагмент со ссылкой (`source`, ещё до двух в `more`) или термин из словаря проекта (`glossary`); `none` — ничего. `answer` — ответ словами, только локальной моделью и только с `consent`, иначе `null` |

## Хук после встречи

Настройки → Встречи → «Команда после встречи». Выключено по умолчанию. Команда запускается через `/bin/zsh -fc` (без login-shell: `~/.zshenv`, `~/.zprofile` и `~/.zshrc` не читаются, `PATH` системный — программы вне `/usr/bin`, `/bin`, `/usr/sbin`, `/sbin` указывайте полным путём) после готовой расшифровки (и ещё раз после сводки, если она готова позже). Путь к папке — первым аргументом (`$1`) и в переменной `MOSTIK_MEETING_DIR`; там же `MOSTIK_MEETING_ID`, `MOSTIK_MEETING_EVENT` (`transcript` или `summary`). Таймаут по умолчанию 60 с, потом процесс останавливается. Вывод — в `~/Library/Logs/Mostik/meeting-hooks.log` (ротация по 1 МБ, три файла). Чувствительные встречи хук не получают.

Пример — копия в Obsidian:

```sh
cp "$1/meeting.md" ~/Vault/Встречи/"$(basename "$1").md"
```

## Фрагмент для пересылки

В расшифровке выделите реплики («Фрагмент» → первая и последняя). «Сохранить» кладёт в `clips/` два файла: `.m4a` (микрофон и система, сведённые в моно, AAC) и `.md` (название встречи, отрезок времени, реплики). Ничего никуда не отправляется. Если аудио уже в Корзине, сохраняется только `.md`.

## Говорящие

У реплик системной дорожки в `transcript.json` есть исходная метка `label` и видимое имя `speaker`. Имена меток лежат в `speaker_names`. У каждой реплики есть уверенность метки `speaker_confidence`; ниже 0,6 стоят `review: true` и `speaker_alternatives`. Голосовая память (выключена по умолчанию, только по согласию) пишет в `transcript.json → voices` лишь подсказки. Векторы голосов хранятся в `<MOSTIK_HOME>/voices/`, а не в папке встречи. Формула, пороги, хранилище и команды движка — `docs/voice-memory.md`.

## Вопросы встречи

`questions.json` пишет движок по строкам живой расшифровки:

```json
{"schema": "mostik.questions", "version": 1, "items": [
  {"id": "q1", "at": 431.2, "track": "system", "speaker": null, "text": "Сколько уходит на видеокарты в месяц?",
   "language": "ru", "layer": "judge", "score": 0.6, "reasons": ["wh", "qmark"], "judge": {"verdict": true, "ms": 410},
   "status": "answered", "answered_at": 437.9, "answered_track": "mic", "answer": "Около 2100 за штуку.",
   "detected_at": "2026-10-11T10:07:11Z"}]}
```

- **Два слоя.** Правила оценивают фразу: вопросительное слово в начале, «ли», инверсия в английском, хвост «да?», знак вопроса. Балл от 0,45 — вопрос, от 0,3 до 0,45 — кандидат. Кандидата проверяет локальная модель, но только если она уже загружена и движок вместе с ней укладывается в 6 ГБ. Дедлайн 2,5 с, после него решают правила. Модель сама не загружается.
- **Статус.** `pending` — ждёт ответа. `answered` — в течение 60 с на другой дорожке прозвучала реплика от трёх слов, не вопрос. `unanswered` — окно прошло или запись кончилась (`status_by`: `live`, `stop`, `transcript`). После точной расшифровки статусы пересчитываются по говорящим, появляется `answered_by`.
- Повтор того же вопроса в пределах 30 с не дублируется.

## Подсказки

Вопрос собеседника (дорожка `system`) ищется по словарю проекта, источникам документов, архиву встреч и полнотекстовому индексу. Текущая и чувствительные встречи в поиск не попадают. Найденное записывается в элемент журнала полем `hint`: вид (`meeting`, `source`, `glossary`), заголовок, фрагмент, путь и строка или время реплики. Включается в Настройках, по умолчанию выключено. Карточка показывается не чаще раза в 20 с и закрывается.

## Кадры окна звонка

- Выключено по умолчанию. Согласие дают на каждую встречу заново — строкой перед стартом или в пилюле. Оно не запоминается.
- Снимается только окно приложения, которое держит микрофон (у браузера — самое большое окно), без курсора, раз в N с (5, 10, 20 или 30; по умолчанию 10). Кадр сохраняется, только если заметно сменился: сетка 64×36, изменилось от 15% клеток, экран перестал двигаться. Не больше 300 кадров на встречу.
- Режим «только текст» — кадры не снимаются. Встреча «только на этом Mac» снимается; облаку и агентам текст кадров не отдаётся (`privacy.drop_sensitive`), как и расшифровка.
- Mostik не запрашивает разрешение «Запись экрана». Если его нет, в окне встречи будет объяснение и ссылки на «Проверку» и Системные настройки.
- В поисковый индекс и в сводку попадают только текст `*.ocr.txt` и путь к кадру, сама картинка не уходит.
