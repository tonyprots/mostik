# Как устроен Mostik

Описание текущего устройства: процессы, цели сборки, модули движка, данные на диске, сеть, сборка и тесты. Точные поля команд и файлов — в договорах, на которые ссылаются разделы.

## 1. Два процесса и шов

Mostik — это два процесса:

- **приложение** на Swift и SwiftUI: клавиши, запись звука, вставка текста, окна, разрешения macOS;
- **движок** на Python: распознавание, словари, причёсывание, расшифровка встреч, архив.

Шов между ними — протокол движка: по строке JSON на команду в stdin, ответы и события — строками JSON в stdout. Ход работы и журнал — только в stderr, приложение пишет его в `logs/engine.log`. Всё, что касается звука и моделей, живёт за швом; всё, что касается macOS, — перед ним. Тесты движка кормят его тем же протоколом: WAV кусками по 100 мс, как приложение.

В выпуске движок запускается встроенным Python из `Contents/Resources/python` с кодом из `Contents/Resources/engine` (`docs/packaging.md`). В debug-сборке путь к Python задаёт `MOSTIK_PYTHON`, код берётся из `engine/` репозитория.

## 2. Цели SwiftPM

```
MostikCore ──┬── MostikKit ──┐
             ├── MostikUI ───┼── Mostik (приложение)
             │               └── MostikBench (замеры)
             ├── MostikCoreTests
             └── MostikSnapshots (+ MostikUI)
```

| Цель | Что внутри |
|---|---|
| `MostikCore` | Логика и форматы данных без AppKit, покрыты тестами: машина состояний диктовки, кодек протокола, настройки и их миграции, история, папка встречи, политика агентных приложений, разбор ответов ИИ встреч, календари (CalDAV и Google через подменяемый транспорт), обновления (`UpdatePolicy`) |
| `MostikKit` | Платформенный слой: запись микрофона (`Recorder`), запись встречи (`MeetingRecorder`: микрофон и звук системы через Core Audio process tap), клавиши (`HotkeyMonitor`, `DeliveryHotkeys`), вставка (`Paster`), чтение поля и выделения через Accessibility, процесс движка (`EngineClient` и расширения по темам), Sparkle, связка ключей, OCR кадров |
| `MostikUI` | SwiftUI: плашка записи, меню-бар, главное окно (Диктовка, Встречи, Словарь, Настройки), онбординг, модель интерфейса `AppModel` |
| `Mostik` | Исполняемый файл: `AppController` и контроллеры по темам связывают Kit, UI и движок |
| `MostikCoreTests` | Тесты ядра со своим раннером (XCTest и swift-testing в Command Line Tools нет); фикстуры прошлых версий настроек — в `Fixtures/` |
| `MostikSnapshots` | Рендер экранов в PNG с демо-данными, без разрешений macOS |
| `MostikBench` | Замеры приложения без окон |

## 3. Движок по группам модулей

Код — `engine/mostik_engine/`, вход протокола — `server.py` (`cmd_<команда>`). Модули transcriber, на которых стоит распознавание, лежат копией в `engine/vendor_transcriber/` (источник — её `SOURCE.md`).

- **Диктовка:** `session.py` (поток PCM → окна по VAD → основная модель → словарь → сомнения), `seams.py` (стыки окон), `models.py` и `model_store.py` (пул моделей и их загрузка), `verifier_worker.py` (проверяющая модель в отдельном процессе), `doubts.py` (отбор слов под вопросом), `language_detect.py`, `power.py` (нагрев и батарея).
- **Словари:** `personal_glossary.py`, `project_glossary.py` (словарь из репозитория), `sources.py` и `extract.py` (папки документов), `calendar_terms.py`, `replace_rules.py`, `vocab_import.py`, `edit_learning.py`, `wordlists.py`.
- **Причёсывание и команды:** `polish.py`, `llm_mlx.py` (локальная модель MLX), `speech_rules.py`, `style_packs.py`, `voice_edit.py`, `intents.py`. Договор — `docs/polish-contract.md`.
- **Встречи:** `meeting.py` (расшифровка двух дорожек через CLI transcriber, диаризация, слияние), `meeting_folder.py` и `meeting_store.py` (папка встречи), `meeting_ai.py`, `meeting_templates.py`, `meeting_recipes.py`, `meeting_hints.py`, `meeting_questions.py`, `meeting_speakers.py`, `speaker_confidence.py`, `speaker_timeline.py`, `voices.py` (голосовая память), `fluid_offline.py`. Договоры — `docs/meeting-folder.md`, `docs/voice-memory.md`.
- **Архив:** `archive.py`, `archive_service.py`, `due_dates.py`, `task_state.py`; индекс подсказок встречи — `index.py`, `ask.py`. Договор — `docs/meeting-archive.md`.
- **Для агентов:** `cli.py` (CLI `mostik`), `mcp.py` (MCP-сервер по stdio), `agent_api.py`.
- **Общее:** `paths.py` (папка данных), `isolation.py` (окружение дочерних процессов — белый список), `privacy.py`, `crash_report.py`, `textnorm.py`.

## 4. Диктовка: путь данных

1. Клавиша нажата (правый ⌥ удержанием или ⌥Space) → `DictationMachine` переходит в запись. Звук параллельно пишется в WAV на диск и уходит в движок кусками по 100 мс.
2. Движок по VAD отрезает законченные окна речи и сразу распознаёт их основной моделью: GigaAM v3 для русского, Parakeet TDT v3 для английского. Готовые окна — событие `partial`.
3. Проверяющая (Whisper Turbo MLX) в отдельном процессе получает пачки соседних окон. Расхождения на терминах становятся словами под вопросом; если проверяющая написала слово из словаря, а основная — похожую ослышку, это исправление.
4. Клавиша отпущена → `stop`. Движок досчитывает хвост, применяет словарь и правила речи, при необходимости причёсывает текст и шлёт `final`.
5. Приложение вставляет текст через буфер обмена и ⌘V, проверяет, что поле изменилось, и пишет запись в историю. Слова под вопросом в текст не попадают: их принимают или отклоняют в истории и на плашке.

## 5. Встречи: путь данных

1. Запись — две дорожки в папку встречи: `mic.wav` (микрофон, «Я») и `system.wav` (звук остальных приложений через Core Audio process tap, macOS 14.2+). Если дорожка встала, запись продолжается новым сегментом.
2. После встречи команда `meeting` прогоняет обе дорожки через CLI transcriber с пониженным приоритетом: микрофон — без диаризации, звук системы — с диаризацией. Реплики сливаются по времени в `transcript.md` и `transcript.json`, эхо собеседника в микрофоне выбрасывается.
3. Имена говорящих ставятся по календарю, по ленте окна звонка (`speaker-timeline.jsonl`), по голосовой памяти (с согласия) или вручную.
4. С согласия на ИИ встреч — заметки по пометкам, сводка и задачи (`notes.json`, `summary.md`).

## 6. Данные на диске

Всё лежит в `~/Library/Application Support/Mostik/` (переопределяется `MOSTIK_HOME`): `settings.json`, история, аудио диктовок, `meetings/<id>/`, личный словарь, кэш словарей проектов, `logs/`. Формат папки встречи — `docs/meeting-folder.md`, JSON-схемы — `docs/schemas/`. Как версии переживают обновление — `docs/release.md`, «Данные между версиями». Модели — в кэше Hugging Face (`~/.cache/huggingface/hub`).

## 7. Сеть

Распознавание и звук в сеть не уходят. Наружу Mostik ходит в таких случаях:

- **модели** — скачиваются с huggingface.co только по кнопке, с проверкой суммы каждого файла;
- **обновления** — раз в день лента `appcast.xml` с GitHub Pages; `.dmg` скачивается по кнопке «Установить»;
- **календари** — Google или CalDAV, если пользователь их подключил;
- **облачное причёсывание и ИИ встреч** — через `claude -p`, только с согласием; встречи «только на этом Mac» в облако не уходят.

Подробно — `PRIVACY.md`.

## 8. Сборка и тесты

- Сборка приложения: `scripts/bundle.sh` собирает `dist/Mostik.app` со встроенным Python, движком и, если есть `vendor/sparkle`, Sparkle. Выпуск, подпись и `.dmg` — `scripts/release.sh`, описание — `docs/release.md` и `docs/packaging.md`.
- Тесты ядра: `swift run MostikCoreTests`.
- Тесты движка: `pytest` в `engine/` (медленные с настоящими моделями помечены `slow`).
- Снимки интерфейса: `swift run MostikSnapshots <папка>`.
- Замеры: `engine/bench/`, описание — `docs/bench.md`.
